## 关键实现边界

- AgentScope 2.0.8 的提示词仅列只读工具，适配器过滤模型提出的写请求；真实模型曾不稳定提出必需的报价/可用性工具，因此服务端基于可信槽位补齐这两项查询。候选占位只由服务端在候选已于前一轮展示且用户明确选择后构造，当前轮刚查询出的候选不能被原始肯定语选中；确认仍由独立接口校验服务端凭据。完整流程是模型语义判断与确定性业务编排的组合，不宜声称全部工具选择都由模型完成。批次中的 `runtime_output_tool_requests` 是适配器策略处理后的输出，不是 Provider 原始工具意图轨迹。
- 模型调用前提交事务，调用后重新锁任务并校验执行代次、fencing token 与任务版本；接管交错测试验证旧执行器失权。恢复事实按任务关系查询，过期/重复回答被拒绝或重放。
- 测试隔离改造前首次全量试跑错误命中了测试库 `public` 表，可能写入了测试数据。没有试跑前快照，不能保证该次未修改公共测试表。随后显式 schema 建表修复，并完成全量回归。本轮额外对 SSE 游标续读/超窗、HTTP 并发确认与操作查询、签名及乱序回执、响应丢失对账定向运行 **35/35 通过**。最新只读统计保留 1,250 个 `case_*` / `exp_*` schema，其中 87 个为空。仓库指令禁止自动删除；如需回收，请用户先核查后手工处理。
- 原有用户修改的 `.workbuddy`、`architecture-verification.json`、两份中文设计文档保留，未由本次任务重写。当前工作区还有本次源码、测试、文档和报告的未提交变更。
