# 门店智能预约 Agent 平台｜简历项目经历

**技术栈：** Python、FastAPI、PostgreSQL、AgentScope、pytest

面向门店预约场景构建 Agent 与预约事务链路，覆盖需求澄清、候选查询、确认提交和中断接管。真实门店数、预约量及个人职责边界待核实。

1. **Agent 决策：** 用 ReAct 式循环处理意图、槽位与结构化工具请求，按任务阶段裁剪模型可见工具；服务端依据可信槽位补齐必需查询，并在用户明确选定候选后构造占位请求。真实模型已跑通一条合成的“查询—选方案—确认—重试”完整预约链路。
2. **工具边界：** 9 项业务工具统一由服务端注入身份、校验参数和角色/阶段许可；300 次构造请求（阶段越权、无权限角色、身份字段注入各 100 次）全部在 handler 执行前拒绝，相关业务表计数前后不变。
3. **预约一致性：** 用 PostgreSQL 区间排他约束拦截资源重叠，配合幂等键、请求摘要和有序资源锁处理重复与并发提交；3,200 次合成数据库争抢最终重叠占用为 0；20 轮 HTTP 同键并发确认均只产生 1 个订单，同凭据换键重放原单、同键异参拒绝。
4. **中断恢复：** 任务与待答问题落库，新 worker 进程按业务账本重建上下文；150 个恢复场景中，50 个等待任务跨进程续办至方案阶段，50 个过期答复被拒，50 个接管交错均拦截旧执行器，旧回复未进入事件流。
5. **回归验证：** 原有 135 项回归加权限、恢复、接管及并发竞争用例，在独立 PostgreSQL schema 下 **187/187 通过**；有锁/无锁并发对照定位直接争抢排他约束时的死锁路径。

这版仅使用已实现和实测的内容；300 次越权请求来自统一工具入口调用测试，不代表外网攻击压测；150 个恢复场景是 50 个待答任务由新 worker 进程续办、50 个逻辑超时注入、50 个接管交错，不包含强杀进程模拟崩溃；3,200 次是[合成数据库实验](/Users/chenyx/Documents/git_project/Agentagent/evals/reports/实验阶段报告_2026-09-23.md)，不代表真实门店流量或完整预约 API 压测。真实模型完成了 3 条合成消息的 v2/v3 重复提示词冒烟对照和 1 条合成完整预约，尚无多场景任务完成率；咨询委派和浏览器写入闭环尚未完成，CI 工作流已加入仓库但云端尚未触发。投递前需根据真实参与情况确认“个人职责”和业务规模。
