- M1 / M2：两个明确版本的真实模型配置，共用同一业务执行器、场景集、工具集和预算。模型 ID 以实验时可用版本为准，不预写效果排名。
- A1：在 M1 上关闭已完成动作摘要/恢复事实重建，只在隔离评测中运行，数据库幂等与权限约束保留。
- A2：在 M1 上改为单轮决策，对比完整“调用—观察—再决策”循环；参数、工具预算和数据保持可比。明确这是决策循环消融，不同时更换模型或工具契约。

服务端身份注入、角色授权与数据库约束是安全门禁，不作为可关闭并运行真实写操作的消融变量。对它们用伪造身份、越权工具与失权执行器的拒绝测试报告拦截率，并核对业务表无非授权写入；消融只改变模型侧上下文或决策策略。

默认规模：M1/M2 各跑 40 个保留场景，每场景 3 次，共 240 次真实模型对话；A1/A2 再各跑 40 × 3，共 240 次。正式评测合计 480 次对话。先在开发集选 10 个样本、两个模型各跑一次做 20 次预算试跑。

每次对话最多 8 个用户轮次、12 次模型请求；每次 Agent 活跃执行工具调用上限沿用明确配置，并额外记录整段对话总工具数。480 次正式评测加 20 次试跑最多 6,000 次模型请求，这是保护性上限，不是预期实际调用量。达到预算记为预算耗尽，不静默丢弃样本。

先用试跑测出每场景实际输入/输出 token，再计算计划成本：总费用 = 各次输入 token × 对应单价 + 输出 token × 对应单价；注意单价单位，并记录缓存命中和工具费用。报告成功任务平均成本时使用全部尝试总费用除以成功任务数，避免漏算失败开销。执行前设置总费用停止阈值；本轮仅制定计划，没有发起付费实验。

| 指标 | 定义 |
| --- | --- |
| 正向任务完成率 | 需要完成预约的场景中，期望订单、任务终态和资源占用同时正确的比例 |
| 场景通过率 | 包含正确澄清、拒绝、转人工等负向场景的整体判据通过比例 |
| 未授权写入率 | 未通过授权/确认的请求造成业务写入的比例，测试观测必须为零 |
| 越权漏放率 | 对抗集中产生未授权业务效果的越权请求数 / 越权请求总数；同时报告请求数和业务效果数 |
| 事实错误率 | 对价格、排班、政策、订单状态等可核对事实，统计与权威业务记录或证据不符的陈述数 / 已审计事实陈述总数；未提供来源的事实陈述单独报告 |
| 结构化输出有效率 | 修复前后分别统计，不能用修复后结果掩盖首次错误 |
| 工具决策正确率 | 符合该步可接受动作集合的比例，不要求唯一固定调用轨迹 |
| 恢复正确率 | 有效任务续办与失效任务正确拒绝分别统计，防止全部拒绝刷高指标 |
| 延迟 | 完整对话及单轮 p50/p95，失败/超时另列；模型、工具和锁等待分别记录 |
| 成本 | 每次尝试、每个成功任务的 token 与费用；缺失 usage 标为未知 |
| 稳定性 | 每场景三次通过分布、错误类型、工具次数和预算耗尽次数 |

统计采用按场景配对的比较，以场景为单位重采样，不把同一场景的三次运行当成三条独立样本。40 个场景只能作为初始工程基准，区间较宽时不宣称显著领先。

硬门禁：新增 CI 工作流，在隔离测试库执行现有及新增必需回归；权限、订单唯一性、资源不重叠、过期执行拒绝等判据在指定测试中无失败才允许合并。真实模型评测单独运行并产出版本化报告，不把外部模型短时波动混入每次合并门禁。模型质量可预设核心正向完成率目标 90%，这是待验证的工程目标；未达到则保留失败报告和改进计划，不改测试分母。模型差异没有稳定证据时如实报告。

固定并保存：git SHA、未提交改动摘要、依赖锁/本地 wheel 哈希、数据库版本与 schema、数据集哈希、时区与时间锚点、模型完整 ID、参数、提示词与工具 Schema 内容哈希、运行预算、provider fingerprint（若提供）、原始脱敏输出、case-level 判定。版本标签必须与实际加载内容一致。

确定性回放使用固定模型响应和确定性时钟验证业务流程；真实模型重复运行验证分布与稳定性。两类报告分开，“固定版本”不表述为输出绝对确定。
